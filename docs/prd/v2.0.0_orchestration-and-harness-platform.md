## 5. 구현 방법

### 5.1 아키텍처 · 구조 (system-architect)

```
 표면       CLI ── 로컬 HTTP + SSE (토큰 · 127.0.0.1) ── [v2.1.0] 웹         server · client · cli
 운영 층    threads · runs · crons · thread 별 직렬 · 크래시 복구            runtime
 회사       swarm(Chief = 기본 진입) ⇄ 에이전트 노드 · handoff MCP            swarm · company · mcp
 그래프     StateGraph · Pregel super-step · Command/Send · interrupt        graph
 라우팅     연결 풀 → 사무실 실행 정책 → Chief 정책 · 슬롯 · 폴백 · 보고      routing
 하네스     claude-code · codex · opencode · lite (+ PreToolUse 가드)        harness · extensions
 저장       sqlite — checkpoint · writes · store · runs · ledger (데이터 폴더)
```

- **의존 방향 단방향** — cli/server → runtime → company → graph · routing → harness. 아래 층은 위 층을 모른다.
- **인스턴스 = 사무실 1개** — 경로 · 데이터 폴더 · 포트는 실행 인자. 한 머신에 여러 고객사 · 엔진 여러 버전이 공존할 수 있다(결정 40).
- **대안 비교** — ⓐ `langgraph` 의존 ⓑ **자체 재구현(채택, 결정 20)**: 노드 안 LLM 호출을 하네스가 대신하므로 LangChain 층이 불필요하고, 원본은 골든 테스트 기준으로만 쓴다. 반증 조건: 골든 시나리오 불일치가 재현 가능하게 늘면 원본 의존으로 되돌린다.

### 5.2 설계 (각 구현 담당)

- **동시성(결정 23)** — 운영 층 · 엔진 · 하네스가 한 asyncio 루프. 동기 노드는 `to_thread`. 동기 얼굴(`invoke`)은 CLI · 테스트용.
- **노드 ↔ 하네스(M21)** — 활성화마다 새 CLI 세션 + 그래프 상태에서 이력 주입. handoff = MCP 도구 `transfer_to_<agent>` → `Command(goto=…)`.
- **실패 처리** — 한도 초과 · 재시도 가능 오류는 그 연결을 빼고 같은 활성화 안에서 다른 연결로 재시도(최대 3회). 남는 예외는 Chief ops thread 로 보고(1시간 1회 제한).
- **가드** — 실행 전 차단은 Claude Code PreToolUse 훅. 승인 필요 명령은 서명과 함께 거부 → 노드가 `interrupt` → 승인 서명만 다음 실행에서 통과.
- **운영 층 직렬화** — 같은 thread 의 run 은 생성 순서대로 하나씩(한 checkpoint 에 두 run 이 동시에 쓰지 않음). 다른 thread 끼리는 병렬.

### 5.3 데이터 (data-engineer)

| 저장 | 위치 | 내용 | 수명 |
|---|---|---|---|
| 고객사 솔루션 리포 | git (고객사마다) | core/ · orgs/ · workspaces/ 정의 | 영구 · 커밋 단위 이력 |
| `state.sqlite` | 데이터 폴더 | checkpoints · writes(태스크 완료 기록) | thread 수명 |
| `runs.sqlite` | 데이터 폴더 | threads · runs | 영구(정리 정책은 v2.3.0) |
| `ledger.sqlite` | 데이터 폴더 | 활성화마다 토큰 · 비용 · 연결 · 모델 | 영구 |
| `secrets.json` | 데이터 폴더 (0600) | API 키 | 사용자가 지울 때까지 |
| `store.sqlite` | 데이터 폴더 | 장기 기억(네임스페이스 KV) | 영구 |

- 직렬화 = 태그 붙인 JSON(메시지 · Send · Interrupt · Command), 미지의 타입만 pickle(자기 서버의 자기 checkpoint 한정).
- 입력 메시지 id = `in-<run id>` — 크래시 복구 때 "이미 들어갔나"를 판정하는 키.

### 5.4 보안 · 권한 (security)

- API 는 127.0.0.1 + 무작위 토큰(데이터 폴더 0600). 비밀값은 리포 밖. 가드 기본 규칙: 재귀 삭제 · 강제 push · hard reset 은 승인 필요.

**PRD 대비 바뀐 것**
- 세션 레지스트리(§D2)를 별도로 두지 않고 운영 층 thread 로 합쳤다(thread = 과제 = 세션).
