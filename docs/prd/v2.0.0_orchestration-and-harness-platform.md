## 4. 구현 방법

> 이 버전은 구현이 끝났다 — 아래 구현 결정은 실제 코드(`python/src/solosquad/`)와 단계 커밋(5008899 · 2779cd2 · a9bf921 · f762419 · a6b10fb · 4733817)을 근거로 기록한다.

### 4.1 아키텍처 · 구조 (system-architect)

```
 표면       CLI ── 로컬 HTTP + SSE (토큰 · 127.0.0.1) ── [v2.1.0] 웹         server · client · cli
 운영 층    threads · runs · crons · thread 별 직렬 · 크래시 복구            runtime
 회사       swarm(Chief = 기본 진입) ⇄ 에이전트 노드 · handoff MCP            swarm · company · mcp
 그래프     StateGraph · Pregel super-step · Command/Send · interrupt        graph
 라우팅     연결 풀 → 사무실 실행 정책 → Chief 정책 · 슬롯 · 폴백 · 보고      routing
 하네스     claude-code · codex · opencode · lite (+ PreToolUse 가드)        harness · extensions
 저장       sqlite — checkpoint · writes · store · runs · ledger (데이터 폴더)
```

- **의존 방향 단방향** — cli/server → runtime → company → graph · routing → harness. 아래 층은 위 층을 모른다.
- **인스턴스 = 사무실 1개** — 경로 · 데이터 폴더 · 포트는 실행 인자. 한 머신에 여러 고객사 · 엔진 여러 버전이 공존할 수 있다(결정 40). → I5

#### I3. 그래프 엔진 — LangGraph 의존 vs 자체 재구현

| 후보 | 방식 | 장점 | 단점 · 비용 |
|---|---|---|---|
| ⓐ | `langgraph` · `langgraph-swarm` 을 런타임 의존 | 구현량 0 · 원본과 자동 일치 | LangChain 층까지 딸려 옴 · 노드 안 LLM 호출이 하네스라 그 층이 불필요 |
| ⓑ | **자체 재구현** — 같은 이름 · 시그니처 · 동작, 원본은 골든 테스트 기준 | 의존 0 · 노드 내부를 하네스로 치환하기 쉬움 | 구현 · 유지 비용 · 원본과 표류 위험 |

- **채택:** ⓑ
- **선택 근거:** 결정 19(LangGraph 완전 모방 — 그래프 · 상태 · 제어 · 영속은 따르고 노드 내부 LLM 호출만 하네스로 치환) · 결정 20(자체 재구현, 원본은 참조 구현 · 골든 테스트, MIT 고지 유지). 커밋 a9bf921 — StateGraph · 채널 · Pregel · Command/Send · interrupt · 서브그래프(`Command.PARENT`) · 체크포인터 · durability · stream 7종을 *"no runtime dependency"* 로 구현, `langgraph` 는 dev 의존(골든 전용). `python/pyproject.toml` dev 그룹 주석 *"never a runtime dependency"*.
- **기각 이유:** ⓐ — 노드 안 LLM 호출을 하네스가 대신하므로 LangChain 층이 불필요하고, 원본은 골든 테스트 기준으로만 쓰면 된다.
