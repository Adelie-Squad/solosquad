## 1. 제품 정의 — 누가 무엇을 하는가

### 1.1 세 부류 (결정 18 → 26~29 재정의)

| 부류 | 누구 | 하는 일 | 고치는 곳 | 채널 · 표면 |
|---|---|---|---|---|
| **본부** | SoloSquad 개발팀(+ 외부 기여자) | 공통 제품 개발 · 고객사 사용 데이터 분석 · 파견 프로젝트 관할 · 승격 후보 리뷰 | 코어 저장소 | git · CLI · 본부 관할 화면(M28) |
| **구축자** | 관리형 = 사람 FDE(창업자) · 셀프 = 사용자 본인. **둘 다 FDE 에이전트와 함께** | 설치 · 도메인 맞춤 · 지속 개선 | 고객사 작업 폴더(`<org>/` 층) — **코어는 건드리지 않는다** | `curl`/`irm` · CLI + 웹 |
| **고객사 사용자** | 사장님(마스터) + 팀원(부서별 권한) | 에이전트에게 일을 맡기고 · 지켜보고 · 승인하고 · 보고받는다 | 없음 | **웹 로그인**(추후 앱) |

### 1.2 두 도입 경로 (결정 26)

| | 관리형 AX | 셀프 |
|---|---|---|
| 설치 | SoloSquad 측이 직접 (`curl`/`irm`) | 사용자가 직접 (`curl`/`irm`) |
| 커스텀 | **3개월** — 사람 FDE + FDE 에이전트 | FDE 에이전트 단독 |
| 본부 연결 · 사용 측정 | 계약에 포함 | 옵트인(권장, M5 · M28) |
| 빌드 | **같은 빌드**(권장) — 차이는 *누가 FDE 를 돕는가* 와 *본부 연결* 뿐 | ← |

### 1.3 이 회사가 "회사"이려면 (2.0.0 최소 조건)

1. **여러 과제가 동시에 돈다** — 과제마다 swarm 하나, 과제끼리는 병렬 (결정 19 · 23)
2. **꺼졌다 켜져도 이어서 한다** — checkpointer + 운영 층의 자동 재개 (M24)
3. **정해진 시각에 스스로 일을 만든다** — cron · goal 이 과제를 생성 (M24)
4. **한 계정이 막혀도 멈추지 않는다** — 활성 풀 안에서 다른 연결로 폴백 (결정 22 · M25)
5. **사람 승인이 필요한 곳에서 멈추고 기다린다** — interrupt (결정 19). 웹에서 승인한다
6. **사장님이 웹에서 지난 일 · 지금 일 · 비용을 본다** — 결정 29 (프로토타입 H1 · H2 · H5)
7. **FDE 에이전트가 회사를 고치고, 본부 업데이트를 받아도 그 커스텀이 남는다** — 결정 27 · 28 (M16 · M29)

**동시성 (결정 23)** — 운영 층 · 엔진 · 하네스 · 표면 서버가 **하나의 `asyncio` 이벤트 루프**에서 돈다. 동기 얼굴은 CLI · 테스트용 포장(`invoke` = `asyncio.run(ainvoke)`).
에이전트 정의 로더 · 파서 · 검증은 평범한 동기 함수로 남는다. 동기 전용 라이브러리는 `asyncio.to_thread`.

**격리** — 과제마다 **git worktree**(§D3) 와 **브라우저 컨텍스트**(결정 25)를 따로 준다.

## 6. 리스크

- **🔴 범위** — 전면 재작성 + 다중 하네스 + 운영 층 + 브라우저 + **FDE + 웹 + 본부**가 한 릴리스에 있다. →
  **세로 슬라이스 1개를 먼저 관통**시킨다: 어댑터 1 · 업무 에이전트 2 + handoff 1 · checkpoint 재개 · **웹에서 승인 1회** · `update` 1회. 그다음 넓힌다. 브라우저 · [4] · 본부 화면은 슬라이스 이후.
- **🔴 FDE 의 자기 수정** — 회사를 고치는 에이전트가 회사를 망가뜨릴 수 있다. → `<org>/` 층만 · interrupt 승인 · 버전 · 롤백 · 코어 쓰기 금지(M29).
- **🔴 고객 데이터** — 로컬 환경 분석 · 사용 측정 · 승격 후보가 모두 고객사 데이터를 만진다. → 분석은 동의 범위 · 읽기 전용 기본 · 본부로는 **메타데이터 기본**(내용은 계약 시에만) · 승격 후보는 고객 데이터 제거 후(M5 · M29 · M30). 개인정보 관련 법령 검토 필요.
- **🔴 커스텀과 업데이트의 충돌** — 본부 업데이트가 고객사 커스텀을 깨면 결정 28 ⑴ 이 성립하지 않는다. → 코어 ↔ `<org>/` 분리를 [0] 부터 · resolve 단일 진입점(M16) · update 후 FDE 회귀 점검 · 롤백.
- **🔴 모방의 표류** — 원본 대비 골든 테스트를 [3] AC 로 강제. 다르게 하고 싶으면 모방 대상표(결정 19)부터 고친다.
- **🔴 swarm 이력 누적 비용** — M12 실측 + M20 주입 규칙.
- **🟡 로컬 서버 외부 접속** — 사장님이 휴대폰으로 보려면 로컬 서버를 밖에서 열어야 한다. → 클라우드(v2.1.0) 전까지 터널 · 중계 방식(M31).
- **🟡 CLI 하네스 의존** — 벤더 출력 형식 변화. → 어댑터 1곳 흡수 · 어댑터별 계약 테스트.
- **🟡 브라우저 안전** — 결제 · 비가역 제출은 interrupt 승인(M27).
- **🟡 프로토타입 ↔ 정식의 간극** — 프로토타입은 더미 데이터 · 백엔드 없음. → 웹 화면을 JSON 경계(결정 10)의 이벤트에 하나씩 연결하며 승격.
- **논거 재유입** — 세션훅 언어 강제 · 시뮬 밀착 · *"swarm 이 아니다"* · *"fde 는 제거됐다"*(→ 결정 27 의 이름 이력 주석). ideation §A3 로 기각.
