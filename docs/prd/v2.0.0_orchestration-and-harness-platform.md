## 1. 제품 정의 — 누가 무엇을 하는가

| 부류 (결정 18) | 하는 일 | 2.0.0 에서의 경로 |
|---|---|---|
| **사용자 개발자** | 도메인 AI 컴퍼니를 구축 · 고객사 맞춤. 작업 폴더(`<org>/`)만 고친다 | git clone (curl/irm 부트스트랩 전까지 유일 경로) → 온보딩 |
| **고객사** | **자기 구독 · API 키를 연결**해 자기 회사로 운영 (BYO, 결정 21 ⑶) | 로컬 서버 + `solosquad chat` |
| **오픈소스 기여자** | SoloSquad 코어 개발 | git fork/clone → PR |

**24시간 회사의 최소 조건** — 2.0.0 이 충족해야 "회사"라고 부를 수 있는 것:

1. **여러 과제가 동시에 돈다** — 과제마다 swarm 하나, 과제끼리는 병렬 (결정 19 · 23)
2. **꺼졌다 켜져도 이어서 한다** — checkpointer + 운영 층의 자동 재개 (M24)
3. **정해진 시각에 스스로 일을 만든다** — cron · goal 이 과제를 생성 (M24)
4. **한 계정이 막혀도 멈추지 않는다** — 활성 풀 안에서 다른 연결로 폴백 (결정 22 · M25)
5. **사람 승인이 필요한 곳에서 멈추고 기다린다** — interrupt (결정 19)

## 2. 아키텍처 — 한 장

```
 표면          solosquad chat (CLI) ── JSON 경계(결정 10) ── [추후] 웹 · 앱 · 메신저
                         │   이벤트 = stream_mode 7종의 직렬화
 운영 층       run manager — threads · runs · crons · store            (M24, LangGraph Server API 모양)
               과제 큐 · 동시 상한 · 크래시 재개 · cron/goal → 과제 생성
                         │
 그래프 엔진   LangGraph 모방(자체 재구현) — StateGraph · Pregel super-step       (결정 19 · 20)
               Command · Send · interrupt · checkpointer · durability
               swarm 층 — create_swarm · handoff 도구 · active_agent
                         │   노드 1개 = 에이전트 1명
 라우팅        연결 → 풀 → 라우팅 (결정 22)
               모델 고르기(작업 적합성) ⟂ 연결 고르기(남은 한도 · 비용 · 동시 슬롯)
                         │
 하네스        claude-code · codex · opencode(API 키 전반) · lite(도구 없는 짧은 작업)   (결정 24)
               §C1 5-메서드 계약 · 노드 내부 LLM 호출만 이 층으로 치환              (M21)
                         │
 도구          MCP — handoff 도구 · 브라우저(Chromium, 결정 25) · 시크릿 · 사용자 MCP
 저장          sqlite3 — checkpoint · store · 세션 레지스트리 · 가계부(토큰 · 비용)   (M26)
```

**동시성 (결정 23)** — 운영 층 · 엔진 · 하네스 · 표면 서버가 **하나의 `asyncio` 이벤트 루프**에서 돈다. 동기 얼굴은 CLI · 테스트용 포장(`invoke` = `asyncio.run(ainvoke)`).
에이전트 정의 로더 · 파서 · 검증은 평범한 동기 함수로 남는다. 동기 전용 라이브러리는 `asyncio.to_thread`.

**격리** — 과제마다 **git worktree**(§D3) 와 **브라우저 컨텍스트**(결정 25)를 따로 준다. 동시 과제가 같은 레포 · 같은 쿠키를 밟지 않는다.

## 3. 단계 (ideation §F′ — 의존 방향 단방향)

> 각 단계는 **자기 블로커가 닫혀야 착수**한다. 블로커 id 는 미결 대장(ideation §0.0.7).

### [0] 골격 — 블로커 없음 ✅
- `uv` 프로젝트 · 패키지 골격 · 스택 10종 + `pandas`(결정 13)
- **에이전트 정의 로더** — `agents/` · `skills/` · `teams/` · `crons/` 를 그대로 읽는다
- **AC:** Given v1.4.3 번들 자산 / When 신 Python 파서로 읽으면 / Then 구 TS 파서와 **파싱 결과가 동등**(골든 테스트, ideation §0.0.5)

### [1] 계약 — 블로커 없음 ✅ (결정 23 · 24 로 해소)
- **하네스 5-메서드**(§C1) + 어댑터 4종의 인터페이스. 실동작 우선순위: `claude-code` → `codex`/`opencode` → `lite`
- **코어 ↔ 표면 JSON 경계**(결정 10) — 이벤트 = stream_mode 7종 직렬화. 로컬 stdio ↔ HTTP 승격 가능한 형태
- **async 경계 명세**(결정 23) — 어디까지 async 인지를 이 단계에서 문서와 타입으로 고정
- **AC:** Given 같은 프롬프트 / When `claude-code` · `opencode` 어댑터로 각각 실행 / Then 같은 `LlmStreamEvent` 시퀀스 형태(start → … → end)와 `parseCost()` 결과를 낸다

### [2] 컨텍스트 — 블로커: M12(실측) · M26 · (M20 은 M12 와 동반)
- **상태 모델** — §B4 `ExecutionContext` = `context_schema`(불변), 대화 · 산출물 = state 채널. 메시지는 **제공사 중립 스키마**(M26)
- **checkpointer · store** — `BaseCheckpointSaver` 모양(get/put/list/put_writes + async), 저장소 sqlite3
- **resolve 단일 진입점** — org 덮어쓰기(agent · **skill**, M16)
- 프롬프트 조립(§D1) · 세션 레지스트리(§D2, 세션 = 과제)
- **주입 규칙**(M20) — *저장은 전부, 주입은 골라서.* 트리밍 기준 = 받는 모델의 컨텍스트 창
- **AC:** Given 과제 진행 중 프로세스 강제 종료 / When 재시작 / Then 마지막 checkpoint 에서 상태가 복원되고 손실된 super-step 은 `durability="sync"` 에서 0

### [3] 실행 — 블로커: M21 · M22 · M24 · M25 · M27 · M10
- **그래프 엔진** — Pregel super-step · `Command`/`Send` · `interrupt`/`resume` · durability 3값. 노드는 동기 · 비동기 둘 다 받는다
- **swarm 층** — `create_swarm` · handoff 도구 · `active_agent` · `default_active_agent` = Chief. 간선은 에이전트 정의에서 선언(M22)
- **노드 ↔ 하네스 치환**(M21) — 권장: *상태가 유일한 진실*, 활성화마다 상태에서 이력 주입. handoff 는 MCP 도구 → `Command(goto=…)`
- **운영 층**(M24) — threads · runs · crons · 과제 큐 · 동시 상한 · 크래시 후 자동 재개 · goal/cron → 과제 생성
- **라우팅 · 연결 풀**(결정 22 · M25) — 연결별 한도 추적 · 동시 슬롯 · 폴백. 작업 적합성 = 에이전트 선호 목록 + 규칙, 애매할 때만 `lite` 분류기
- **브라우저 도구**(결정 25 · M27) — Chromium 을 소유하는 MCP 서버 1개, 과제별 컨텍스트, 결제 · 비가역 제출은 interrupt 승인
- §D3 worktree + 85% 자동 교대 · §D4 가드 · 훅 단일 명세(어댑터 이벤트에 결선)
- **AC (골든):** Given LangGraph 원본과 같은 그래프 · 같은 입력 / When 자체 엔진으로 실행 / Then **상태 전이 · `stream_mode="updates"` 시퀀스가 원본과 동일**(결정 20 — 원본은 **테스트 전용 dev 의존**으로만 설치)
- **AC (회사):** Given 활성 연결 2개 · 동시 과제 5개 / When 연결 1개가 한도 초과 / Then 진행 중 과제는 다음 노드부터 다른 연결로 계속되고, 사용자 개입 없이 5개 모두 완주

### [4] 분석 — 결정 6
- 채점 · 마이닝 · 평가를 Python 생태계로. 장기 사이클 작업 · 시뮬 기반(기능은 v2.4.0)
- 가계부(M26)를 읽는 비용 · 품질 리포트

### [5] 표면 — 블로커: M17 · M18
- `solosquad chat`(유일 표면, §B6) · `agents watch`
- **온보딩** — 도메인 선택(M17) → **자격증명 연결**(결정 22: 구독 로그인 n개 · API 키 n개 · 활성 토글) → 작업 폴더 생성
- **AC:** Given 신규 설치 / When 온보딩에서 구독 1개 로그인 + API 키 1개 입력 후 하나를 비활성 / Then 라우팅 후보에 활성 연결의 모델만 나타난다

### [6] 배포 — 블로커: M5 · M2 · M15
- git clone 경로 확정(기여자 + 부트스트랩 전 사용자 개발자) · `curl`/`irm` 부트스트랩 + 릴리스 압축본(SHA-256) · npm deprecate 안내

## 6. 리스크

- **🔴 범위** — 전면 재작성 + 다중 하네스 + 운영 층 + 브라우저가 한 릴리스에 있다. → [0]~[3] 을 **세로 슬라이스 1개**(어댑터 1 · 에이전트 2 · handoff 1 · checkpoint 재개)로 먼저 관통시키고 넓힌다. [4]·브라우저는 슬라이스 이후.
- **🔴 모방의 표류** — "완전 모방"이 구현 중 조금씩 어긋나는 것. → 모방 대상표(ideation 결정 19)를 기준선으로, **원본 대비 골든 테스트**를 [3] AC 로 강제. 다르게 하고 싶으면 표부터 고친다.
- **🔴 swarm 이력 누적 비용** — 기본 handoff 가 전체 이력을 넘겨 컨텍스트가 단조 증가. → M12 실측 + M20 주입 규칙. 기본값은 실측 전까지 보수적으로.
- **🔴 CLI 하네스 의존** — 노드 내부가 외부 CLI(Claude Code · Codex · OpenCode)라 벤더 출력 형식 변화에 노출. → §C1 개선안 5(벤더 회귀 흡수점 = 어댑터 1곳) 유지 · 어댑터별 계약 테스트.
- **🟡 헤드리스 로그인** — 구독 로그인은 브라우저 창 전제. 로컬은 문제없고 클라우드(v2.1.0)에서 터진다. → M25 ⓑ 를 v2.1.0 착수 전 해소.
- **🟡 브라우저 안전** — 에이전트가 결제 · 계정 변경 · 비가역 제출을 할 수 있다. → §D4 가드 + interrupt 승인 · 과제별 컨텍스트 격리(M27).
- **🟡 동시성 전염** — 결정 23 으로 async 영역이 넓어졌다. → async 경계를 [1] 에서 명세하고 로더 · 파서 · 검증은 동기로 고정.
- **논거 재유입** — 폐기된 논거(세션훅 언어 강제 · 시뮬 밀착 · *"swarm 이 아니다"*)가 다시 등장. → ideation §A3 · 결정 19 인용으로 즉시 기각.
