## 1. FDE 에이전트 (결정 27)

| 기능 | 내용 | 미결 |
|---|---|---|
| **대화형 온보딩** | 사업 · 업무 · 쓰는 도구를 대화로 묻는다 → **도메인 묶음** 선택(예: 소상공인 커머스 AX) → `<org>/` 층에 팀 · 에이전트 · 스킬 · cron · 워크플로 정의 작성 | **M17** |
| **도메인 · 로컬 분석** | 사용자가 지정한 폴더 · 앱만 **읽기 전용**으로 본다(엑셀 결산 파일 · 주문 내보내기 등) → 업무 지도 · 자동화 후보. **결과는 고객사 서버 밖으로 나가지 않는다** | 결정 34 · 37 |
| **개선 주기** | cron 으로 돈다 — 가계부 · 실패 · 승인 거절 이력을 읽고 정의 수정안을 낸다 | 결정 34 |
| **변경 관리** | 쓰기 대상 = **`curl`/`irm` 으로 받은 고객사 솔루션 = 고객사의 별도 git 저장소**뿐, 코어 불가. 수정 1건 = 제안 → 웹 승인 → **커밋 1개** → 문제 시 `git revert` | 결정 34 · 37 |
| **공통 개선 후보** | 공통 제품으로 갈 만한 개선은 **에이전시 FDE** 에게 보낼 후보로 고객사 저장소 안에 쌓아둔다. 전송 · FDE ↔ FDE 소통은 v2.3.0 | 결정 37 |
| **Nudge** | "이런 것도 맡길 수 있어요" 안내 — 사용 패턴 기반 | 결정 34 |
| **스레드 위치** | 업무 스레드(Chief 진입)와 분리된 **FDE 스레드**(cron · goal 이 띄움). 사장님과의 FDE 대화는 웹의 별도 채널 | 결정 27 주석 |

## 2. 브라우저 도구 (결정 25)

- SoloSquad 가 Chromium 을 소유하는 **MCP 서버 1개** → 모든 어댑터에 같은 도구(열기 · 읽기 · 클릭 · 입력 · 캡처)
- **과제마다 브라우저 컨텍스트 분리**(쿠키 · 저장소) · 동시 브라우저 상한
- 로그인 상태(쿠키) 보관 = 시크릿과 같은 규칙(로컬 keychain / 암호화 파일)
- **결제 · 계정 변경 · 비가역 제출은 interrupt 승인**(§D4)
- 미결 = **M27**

## 3. 분석 (결정 6)

- 채점 · 마이닝 · 평가를 Python 생태계로 · 장기 사이클 작업
- **FDE 개선 주기의 입력**(무엇이 자주 실패하나 · 어디서 승인이 거절되나 · 어디에 비용이 몰리나)이자 v2.3.0 사용 요약의 원천

## 4. AC

- Given 신규 고객사 / When FDE 와 온보딩 대화 15분 / Then 도메인 묶음 1개가 깔리고 첫 워크플로 1개가 웹에 켜진다
- Given FDE 가 스킬 수정을 제안 / When 사장님이 거절 / Then 정의 파일은 바뀌지 않는다. 승인 후 적용된 변경은 명령 한 번으로 직전 버전으로 돌아간다
- Given 분석 동의 폴더 1개 / When FDE 가 로컬 분석 / Then 그 폴더 밖 파일 접근 시도 0건 · 쓰기 0건
- Given 과제 2개가 동시에 같은 사이트에 로그인 / When 브라우저 도구 사용 / Then 두 과제의 쿠키가 섞이지 않는다
- Given 에이전트가 결제 버튼을 누르려 함 / When 브라우저 도구 호출 / Then 승인 전에는 실행되지 않는다

## 5. 스코프

**In:** FDE 에이전트(위 표) · 도메인 묶음 형식 + 첫 묶음 1종(커머스) · 브라우저 MCP · 분석.
**Out:** 승격 후보를 에이전시로 보내기 · 업데이트 중개(→ v2.3.0) · 클라우드 헤드리스 브라우저(→ v2.4.0).

## 6. 리스크

- **🔴 FDE 의 자기 수정** — `<org>/` 만 · 승인 · 버전 · 롤백 · 코어 쓰기 금지(M29).
- **🔴 고객 데이터** — 로컬 분석은 동의 범위 · 읽기 전용 기본. 분석 결과는 고객사 서버 밖으로 나가지 않는다(에이전시 전송은 v2.3.0 의 동의 규칙을 따른다).
- **🟡 브라우저 안전 · 사이트 약관** — 자동화가 금지된 사이트가 있다. 도메인 묶음마다 사용 사이트 목록과 주의를 둔다.
