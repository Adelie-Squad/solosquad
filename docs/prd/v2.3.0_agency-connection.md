  이 마이너가 끝나면 **셀프 경로가 `curl`/`irm` 한 줄로 시작**되고, 관리형 고객사들을 에이전시에서 한눈에 볼 수 있다.

## 1. 범위

| 영역 | 내용 | 결정 · 미결 |
|---|---|---|
| **설치** | `curl`/`irm` 부트스트랩 → 태그별 **릴리스 압축본**(제품 목록만 · SHA-256) → 온보딩(FDE) | 결정 18 · **M15** |
| **릴리스** | CI 가 태그마다 압축본 + 해시 + **릴리스 노트**(공통 · 고객사 영향 항목 포함) | M15 |
| **업데이트 (FDE 중개)** | 새 릴리스 감지 → FDE 가 **그 고객사 기준으로 설명**(바뀌는 것 · 커스텀 충돌) → 사용자와 **적용 · 보류 · 건너뛰기** → 적용 시 코어만 교체 · `<org>/` 보존 · 회귀 점검 · 실패 시 직전 코어로 | **결정 31** |
| **사용 측정** | 고객사 → 에이전시: heartbeat · 사용 요약(**메타데이터만** — 과제 · 승인 · 실패 횟수, 토큰/비용 합계, 코어 버전, 오류 유형) · **가명 설치본 ID**. 동의 = 관리형 계약 · 셀프 옵트인 · 나간 내역을 웹에서 열람 · 보관 12개월 | 결정 28 · 34 · 37 |
| **에이전시 최소판** | 수신 서버 + **가명 설치본 목록** · 상태 · 코어 버전 · 최근 오류. **고객사 이름 · 연락처는 받지 않는다** — ID ↔ 고객사 대응표는 SoloSquad 밖(관리형 계약 기록). 관할 = 지켜보고 돕기. 지원 범위 = **최신 + 직전 2개 마이너** | 결정 30 · 34 · 37 |
| **승격 = FDE ↔ FDE** | 고객사 FDE 가 공통 개선 후보(provenance · **비식별**)를 에이전시로 보낸다 → **에이전시 FDE 가 별도로 판단** → 채택 시 SoloSquad 저장소에 PR(머지는 개발자) → 다음 릴리스. 두 FDE 는 이 **FDE 채널**로 질문 · 답 · 업데이트 안내를 주고받는다 | 결정 37 · **M30** · **M32** |
| **npm 정리** | 레지스트리의 구 `solosquad` 는 게시 유지 + deprecate 로 curl 설치 안내 | 결정 34 |
| **docs 게이트** | npm 전제의 docs-freshness 게이트를 Python · 압축본 판으로 재작성 | — |

## 2. AC

- Given 새 컴퓨터 / When `curl … | sh`(또는 `irm … | iex`) / Then Python 사전 설치 없이 설치되고 해시 검증 실패 시 중단된다
- Given 에이전시가 새 코어를 릴리스 / When 고객사 FDE 가 받음 / Then 그 고객사 기준 설명과 적용 · 보류 · 건너뛰기가 웹에 뜨고 **사용자가 고르기 전에는 코어가 바뀌지 않는다**
- Given `<org>/` 에 커스텀 스킬 2개 / When 업데이트 적용 / Then 커스텀 2개가 그대로 로드되고 회귀 점검이 통과한다. 실패하면 직전 코어로 자동 복귀한다
- Given 셀프 사용자가 측정에 동의하지 않음 / When 24시간 구동 / Then 에이전시로 나가는 요청 0건
- Given 관리형 설치본 3곳 / When 에이전시 화면 / Then 세 곳의 상태 · 코어 버전 · 최근 오류가 **가명 ID 로** 보이고, 고객사 이름은 에이전시 쪽 어디에도 없다
- Given 고객사 FDE 의 승격 후보 / When 에이전시로 전송 / Then 후보에 고객사 정보(대화 · 파일 내용 · 고객사 · 사람 이름 · 연락처)가 없고, 에이전시 FDE 가 판단 결과를 FDE 채널로 돌려준다
- Given 고객사 FDE 가 에이전시 FDE 에게 자유 텍스트 질문 / When 전송 / Then 비식별 필터를 통과하고 사장님 확인을 거친 내용만 나가며, 고객사 웹 *나간 내역* 에 남는다

## 4. 리스크

- **🔴 고객사 정보 유입** — 고객사 → 에이전시 전송이 처음 생긴다. → **고객사 정보는 들어오지 않는다**(결정 37): 메타데이터 · 가명 ID · 비식별 후보 · 메시지만 · 나가는 쪽 필터 + 받는 쪽 재검사 · 나간 내역 열람. 관련 법령 검토.
- **🔴 버전 분산** — 보류한 고객사가 생겨 현장에 여러 코어 버전이 공존한다. → 지원 범위 규칙(M28) · 하위 호환 정책.
- **🟡 공급망** — curl 설치는 중간자 · 저장소 탈취에 노출. → 버전 핀 + SHA-256 · 파일로 받아 확인 후 실행하는 경로 병기([[260818-agent-distribution-channels]] §L.1 · §G.3).
