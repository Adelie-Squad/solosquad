## 1. 목표

- **major(v2.x):** roadmap §2.6 — *"SoloSquad 는 솔로프러너 · 소규모 비즈니스에게 에이전트 회사를 맞춤형 AX 솔루션으로 제공하는 에이전시"*.
- **minor(2.1.0):** **"사장님이 웹에 로그인해 회사에 일을 맡기고, 지켜보고, 승인하고, 보고받는다 — 실제로 작동하는 AI 기능과 함께."**
- **이 버전이 맡는 조각:** v2.0.0 엔진 위에 고객사 웹 표면(로그인 · 승인 · 보고)을 얹고, **고객사 소유 클라우드에 구축 → 인계하는 관리형 파일럿의 시작점**을 만든다(결정 33 — 순서 기준 = 관리형 파일럿을 가장 빨리 시작할 수 있는 순서 · 결정 46).
  - ~~rev4: 창업자 로컬 작업 → 프라이빗 git → Cloudflare 배포(결정 39)~~ → 결정 46 W1 로 대체.
- **이 버전이 지키는 원칙(결정 43 P1~P3)** — 이 버전의 모든 결정은 셋 중 하나와 충돌하면 원칙 쪽으로 고친다.
  - **P1 고객 소유** — 클라우드 계정 · 결제 · 서버 · 도메인 · LLM 계정 · 코드 리포 전부 고객 명의. 에이전시는 고객 계정 위에 구축하고 인계한다(관리형 3개월 뒤 고객이 완전 제어). → W1 · W4 · W16
  - **P2 지역 적합** — 지역 프로필(나라별 법 · 제공사 지원 지역 · 데이터 규정) 안에서 합법이고 가장 적합한 서비스만 쓴다. 제공사 사용 자격 규칙을 따르고 **위치를 숨기거나 바꾸는 기능은 넣지 않는다**. → U3 · U4 · W17 · §3.3
  - **P3 내부 업무 도구** — 사용자는 대표 · 직원뿐, 외부 가입 없음. 접속은 결정 41(인터넷 + 강한 로그인 기본). → W3 · W7 · U2
- **이 버전이 끝나면** 관리형 PoC 를 시작할 수 있다: 에이전시 FDE 가 **고객 명의 클라우드 계정에 VM 1대**를 구축(관리형 git clone + uv, 결정 48 · W16) → 고객 도메인 + TLS → 대표 · 직원이 웹에 로그인해 실제 작동하는 AI 기능을 쓴다. 사람 FDE 가 3개월 커스텀을 시작하고, 끝나면 인계 체크리스트로 넘길 수 있는 상태.

### 3.4 인수 조건

```
C1  Given  고객사 A · B 가 각자 배포됨
    When   A 계정으로 로그인
    Then   A 의 회사만 보이고 B 의 도메인 · 데이터에는 A 계정으로 접근할 수 없다

C2  Given  로그인하지 않은 방문자
    When   고객사 도메인 접속
    Then   로그인 화면 외에는 어떤 API 도 응답하지 않는다

C3  Given  org 2개(테슬라 · 스페이스X) 계정을 둘 다 가진 사람
    When   계정 전환
    Then   전환한 org 의 사무실만 보인다

C4  Given  내부망 유형 사무실
    When   사내망 밖에서 접속
    Then   로그인이 맞아도 사무실 검증에서 막히고 *사내망에서만 열립니다* 안내가 뜬다

C5  Given  팀 3개(재무 · 소싱 · 마케팅)
    When   사무실 화면
    Then   팀마다 소속 에이전트와 지금 하는 과제가 보인다

C6  Given  과제가 승인 대기로 멈춤
    When   사장님이 웹에서 승인
    Then   그 지점부터 이어지고 승인자 · 시각이 기록된다

C7  Given  자리를 비운 8시간 동안 과제 3개 완료
    When   접속
    Then   첫 화면에 3개의 보고와 비용 합계가 보인다

C8  Given  실행 정책이 `외부 API 금지` 인 사무실
    When   라우팅
    Then   외부 API 키가 있어도 사내 · 로컬 모델로만 간다

C9  Given  연결 1개 월 예산 80%
    When   Chief 가 감지
    Then   웹에 경고와 제안(다른 연결 · 예산 조정)이 뜬다

C10 Given  에이전시 FDE 가 고객사 솔루션 리포에 push 하고 고객 VM 에서 갱신(관리형 git clone · 결정 48)
    When   인스턴스 재시작
    Then   진행 중 과제는 이어지고 데이터 폴더는 유지된다

C11 Given  웹 서버 재시작
    When   다시 접속
    Then   로그인 세션은 만료 전까지 유지되고 대화 · 과제가 그대로다

C12 Given  `access` 를 따로 설정하지 않은 사무실(기본값)
    When   임의의 인터넷 주소에서 고객사 도메인에 접속
    Then   로그인 화면이 뜨고, 로그인(패스키 또는 OTP)에 성공하면 사무실이 열린다 — 로그인 없이는 C2 와 같이 막힌다
```

### 4.2 설계 (frontend · backend)

- **웹 스택** — React + Vite + TypeScript(프로토타입과 동일). 웹은 같은 레포 `web/`(TS · React)로 결정 34(M31 ③)에서 닫혔다 — 검토한 대안 없음.
- **화면 순서** — 프로토타입의 Arc 레이아웃 · 사무실 · 대화 · 승인 · 워크플로 · 비용을 결선 순서대로.
- **(rev5) 웹 = 하나의 제품**(결정 44) — 고객사별 차이는 설정(I31) · 선언형 화면(I30)으로만 둔다. 고객사별 코드 분기는 만들지 않는다.
