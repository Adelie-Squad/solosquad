## 1. 목표

- **major(v2.x, 인용):** roadmap §2.6 — 솔로프러너 · 소규모 비즈니스용 맞춤형 AX 에이전트 회사. v2 요구 기능에 **"데이터 분석 · 시뮬레이션 · 사이클 장기 작업"** 이 들어 있다(결정 6). `[보강 필요: v2 목표 안에서 이 기능의 자리 — 고객사 사업용인지 에이전시 기획용인지, S5]` *(이관 전 원문의 major = v1.x **애자일 · 실험 중심 기획**.)*
- **minor(v2.5.0):** roadmap §5.3 — **"가상 시장 수요검증 시뮬레이션 *기능* — 캘리브레이션-증강 스크리닝. 연구 결론: raw NO-GO, 캘리브레이션 부분 회복(~0.64)."**
- **이 버전이 맡는 조각:** **0-to-1 제품의 유료 전환 수요를 합성 페르소나 가상시장으로 사전 스크리닝**해 기획 워크플로(new-build)에 탑재한다.
- **이 버전이 끝나면** new-build 워크플로에서 아이디어 후보를 시뮬로 shortlist 하고, 실측 fake-door 로 확정하라는 권고까지 받을 수 있다 — **랭킹/스크리닝 보조**이지 수요 예측기가 아니다.

**배경 — 연구가 정한 전제(그대로는 만들지 않는다).** 8사이클 blind 백테스트 결론(final-result §1 ~ §6):

- **raw 1회성 시뮬 = 反예측(NO-GO).** framing 3 × aggregation 6 × 시간축 어디서도 성공 > 실패 판별 불가(구조적). 원인 — LLM 페르소나는 *상상된 매력*을 추종하고 *실제 revealed behavior* 에 접근하지 못한다.
- **캘리브레이션 = 부분 회복**(LOO 0.40 → 0.64, N=14), **sim → real 비단조**(3-regime: 니치-실수요 · 광범위-매력 실패 · 옳게 거부된 dud). 단순 · regime-aware 보정 모두 ~0.64 에서 정체(C8 개선 0). **절대 수요 추정 불가, 랭킹/스크리닝만.**
- **재사용 자산(즉시 유효)** — **blind + 누출통제 백테스트 프로토콜.** 어떤 수요-시뮬 방법이든 유효성을 채점하는 표준 게이트.
- **실제 제품 적용 caveat** — 토론철 시뮬 p_pay ~0.14 vs 창업자 B2C 목표 전환 5%(~3배 과대예측). 신규 제품엔 실측 라벨이 없어 **소규모 fake-door 실측 앵커 확보가 선결**.
- 연구 셋업 — Nemotron-Personas-Korea(~100만 한국 인구기반 페르소나) · Qwen2.5-7B-Instruct · 200 personas/case · seed 42 · A100×2.
- → 그러므로 기능은 원시 예측기가 아니라 **(a) 캘리브레이션-증강 스크리닝 특징 (b) 진단 경고 플래그 (c) 유효성 게이트(blind 백테스트)** 로 설계한다.

## 4. 구현 방법

> R9 — 착수 시 담당 에이전트(data-analyst · data-engineer · backend · product-manager)가 v2 런타임(S5) 기준으로 리뷰해 확정한다. 아래는 연구 결론에서 직접 나온 결정만 옮겼다.

### 4.1 아키텍처 · 구조

파이프라인 — 페르소나 표본 → LLM 페르소나 에이전트 결정(관심 / 전환 / 이탈) → raw 점수(내부 특징) → 캘리브레이션 매핑(앵커 학습) → 보정 랭킹 + 진단 플래그 → new-build 스크리닝 UX. 배포 경로에는 blind 백테스트 게이트가 선다.

#### I1. 시뮬 출력을 기획에 쓰는 방식

| 후보 | 방식 | 장점 | 단점 · 비용 |
|---|---|---|---|
| ⓐ | raw 시뮬 = 수요 예측기 | 단순 · 실측 불필요 | **反예측** — 연구가 NO-GO(C1~C5 사이클 모두 판별 실패, 구조적) |
| ⓑ | **캘리브레이션-증강 스크리닝 특징** — 시뮬을 *특징*으로 취급, 실측 앵커로 sim → real 매핑 학습, 보정 예측만 사용 + 진단 플래그 + 유효성 게이트 | 부분 회복(LOO 0.40 → 0.64) · 실측 확정 전 shortlist | 상한 ~0.64 · 실측 앵커 필요 |
| ⓒ | 시뮬 미탑재 — 실측 fake-door 만 | 오도 위험 없음 | 연구가 확인한 부분 회복 신호를 쓰지 않음 |

- **채택:** ⓑ.
- **선택 근거:** final-result §6 기능화 권고 — *"raw = NO-GO · 캘리브레이션-증강 = 조건부 · 부분 GO · 현 상한 ~0.64 는 명시"*.
- **기각 이유:** ⓐ — 연구가 반증(잘못된 방향 유도) · ⓒ — 연구 판정이 조건부 GO 이고, ⓑ 도 최종 확정은 fake-door 로 넘기므로 ⓒ 의 안전성을 포함한다.
- **반증 조건:** 확장 코퍼스(수십~수백 사례, final-result §8)에서 캘리브레이션 LOO 가 chance 수준으로 떨어지면 ⓒ 로 후퇴.
- **부작용:** 사용자가 보정 랭킹을 수요 예측으로 오독할 위험(→ §5 K2) · 앵커 의존(→ §5 K3).

#### I2. 캘리브레이션 매핑 형태

| 후보 | 방식 | 장점 | 단점 · 비용 |
|---|---|---|---|
| ⓐ | 단순(단조) 보정 | 단순 · 소표본에 안정 | sim → real 이 비단조(3-regime)라 표현 한계 |
| ⓑ | **regime-aware 보정**(2특징) | 비단조 3-regime 구조를 반영 | 연구 C8 에서 ⓐ 대비 개선 0(둘 다 0.64) · 키워드 기반 regime 정의 |

- **채택:** ⓑ(원문 범위 ② "regime-aware").
- **선택 근거:** final-result §3 — 비단조 3-regime 이 상한을 만든다. 단 C8(N=14)에선 개선이 측정되지 않았다.
- **기각 이유:** ⓐ — 비단조 구조를 원리적으로 못 담는다. `[보강 필요: C8 개선 0 을 감안한 채택 재확인 — 착수 시 담당 에이전트]`
- **반증 조건:** 확장 앵커 코퍼스에서도 ⓑ 가 ⓐ 대비 개선이 없으면 ⓐ 로 단순화.
- **부작용:** regime 정의가 키워드 기반이라 새 도메인에서 오분류 가능(→ §5 K1).

### 4.2 설계

#### I3. 페르소나 원천

- **검토한 대안 없음** — 연구 셋업(인구기반 페르소나, Nemotron-Personas-Korea)을 승계한다. 원천 다양화(한국 외)는 설계 대안이 아니라 범위 결정이라 S2 로 보냈다.
- **반증 조건:** S2 에서 다국 시장을 열기로 하면 원천 후보 비교를 새로 연다.
- **부작용:** 문화 confound(→ §5 K5).
- 모델 실행 — `[보강 필요: 페르소나 에이전트를 돌릴 연결 · 모델(연구 = Qwen2.5-7B 단일), S5-3]`.
- 분석 의존성 — S4.

#### I4. 유효성 게이트

- **검토한 대안 없음** — 연구가 blind + 누출통제 백테스트를 *"향후 어떤 수요-시뮬 방법이든 유효성을 채점하는 표준 게이트"* 로 권고했다(final-result §6). 같은 프로토콜을 배포 전 자가채점(C1)에 쓴다.
- **반증 조건:** 누출 감사에서 익명화 vs 원본 격차가 임계를 넘으면(암기) 게이트 데이터셋을 교체.
- **부작용:** 게이트 실행 비용 · 시간 — `[보강 필요: 1회 실행 비용 실측]`.

**AI 부록(R6)**

- **① 허용 답변 범위** — 아이디어 후보의 **보정 랭킹 + 진단 플래그 + 실측 fake-door 확정 권고**, "랭킹/스크리닝 보조" 표기와 현 상한(~0.64) 동반. 절대 전환율 · 원시 시뮬 값을 주장하는 답은 범위 밖(연구가 반증).
- **② Eval Plan** — 연구 rubric(`research-plan §5`) 재사용, 통과선은 실험 전 고정값 그대로:

  | 기준 | 통과선 |
  |---|---|
  | 방향 정확도 | ≥ 4/5 사례 방향 일치 **AND** baseline 대비 +마진 |
  | baseline 우위 | ≥ 2개 지표에서 무시뮬 LLM · base-rate 초과 |
  | 캘리브레이션 | ECE ≤ 0.15(reliability diagram) |
  | 누출 통제 | 익명화 vs 원본 성능 격차 ≤ 임계(암기 아님) |
  | 리뷰(verifier) | overall ≥ 4(Weak Accept), 4축 각 ≥ 3 |
  | **배포 게이트** | **캘리브레이션 LOO 가 chance · raw 상회** |

  사례 셋 = 연구 백테스트 사례(N=14)에서 시작 → R6 권장 20~30 케이스로 확장 · 운영 중 누적. `[보강 필요: 확장 사례 확보 방법 — 연구 후속은 수십~수백 사례 코퍼스]` 프롬프트 · 모델 · 캘리브레이션 수정마다 **전체 재실행(회귀)**.
- **③ 실패 정의 + 가드레일** — 실패 = 절대 수요 주장 · raw 노출 · 앵커 없는 자동 판정 · 게이트 미통과 버전 배포. **Always do** = 보정 랭킹만 · 상한 표기 · fake-door 확정 권고 · 배포 전 게이트. **Ask first** = `[보강 필요]`. **Never do** = 절대 전환율 주장 · raw 시뮬 직접 노출 · 실측 앵커 없는 신규 제품 자동 판정.
- **④ 3단계 평가 피라미드** — 규칙 기반(rubric 수치 지표 · 출력 규칙 검사) → LLM-as-Judge(verifier subagent overall ≥ 4) → 사람 · 현실(실측 fake-door 대조). 일상 = 규칙 + 판정, 중대 변경 = 실측 대조까지.
