# 프로토타입 — 소규모 비즈니스용 AI 직원 '하루' 웹 인터페이스

> **상태:** 프로토타입 초안 (2026-10-14) · 고객 미팅 피드백 4종 반영 (2026-10-25 — 토큰 사용량 · 엑셀 재무 자동화 · 업무 카테고리 · 팀원 권한) · 물류/커머스 시나리오 + 워크플로우 3종 · 사무실 · 부서 3곳 + 아이소메트릭 사무실 (2026-10-28) · **성격:** 정식 기능 전 데모 — 화면·흐름 검증용. 백엔드·실 연동 없음, 전부 더미 데이터.
> **위치:** `prototype/ax-agent-web/` (TypeScript · React · Vite) · **실행:** `npm install && npm run dev` → http://localhost:5180
> **관계:** SoloSquad v2.x 계보와 독립. 채택 시 `docs/prd/` 로 승격하고 결정 1~17(`docs/ideation/260803-…` §0.0)과 정합을 다시 본다.

## 0. 한 문장

소규모 비즈니스 사장님에게 **AX(AI 전환) 솔루션을 'AI 직원' 한 명의 형태로** 제공하고,
사장님은 이 웹 화면에서 **직원이 한 일을 보고받고, 지금 하는 일을 지켜보고, 일을 맡긴다.**

## 1. 문제와 대상

- **대상:** 직원 0~5명 규모의 소규모 커머스 · 물류 사업자(데모 시나리오 = 중국 공장에서 생활용품을 수입해 스마트스토어 · 쿠팡 · 자사몰에서 파는
  가상 회사 '모아 리빙', 김포 창고. 회사 · 사람 · 공장은 모두 가상).
- **하루가 맡는 3대 업무 = 워크플로우 3종:** 재무 관리 · 상품 소싱 · SNS 자동화.
- **문제:** 메일·리뷰·재고·매출 정리 같은 반복 업무가 사장님 1인에게 몰린다. 기존 SaaS 는 도구를 *주는* 방식이라
  "설정하고 운영할 사람"이 또 필요하다.
- **가설:** 도구 대신 **직원처럼 행동하는 개인용 에이전트**(참조 — Meta Muse · OpenAI dots · SpaceX AI Grokbot 류의
  개인 에이전트 경험)로 주면, 사장님은 "설정"이 아니라 "보고받고 승인"만 하면 된다.

## 2. 이 프로토타입이 검증하려는 것

| # | 질문 | 확인 방법(데모) |
|---|---|---|
| H1 | 접속하자마자 **"지난 접속 이후 무엇을 했는지"** 를 보여주면 신뢰가 생기는가 | 홈 — 봇 인사 + 보고 카드 |
| H2 | **지금 진행 중인 일**이 항상 보이면 "맡겨도 된다"는 느낌이 드는가 | LNB 실시간 작업 + 상세 뷰 |
| H3 | **추천 프롬프트**가 "무엇을 시킬 수 있는지" 모르는 문제를 푸는가 | 홈 추천 칩 · 커맨드 바 |
| H4 | 메일·Task·스케줄러를 **한 셸(Arc 레이아웃)** 에 모으면 탐색 비용이 낮은가 | 사이드바 고정 타일 6개 |
| H5 | **토큰 사용량(=비용)** 을 부서·작업별로 보여주면 "얼마나 쓰는지 모르는 불안"이 줄어드는가 | 사무실 › 대시보드 토큰 섹션 |
| H6 | 사장님이 이미 쓰는 **엑셀 결산 파일을 그대로 올리면** 재무 대시보드가 채워지는 흐름이 온보딩 장벽을 낮추는가 | 워크플로우 › 재무 관리 — 엑셀 올리기 → 손익표 |
| H10 | 에이전트들을 **사무실의 직원처럼** 부서 스테이션에 앉혀 보여주면(사무실 TV 상시 화면 포함), 여러 에이전트가 동시에 일하는 상황을 한눈에 이해하는가 | 사무실 — 부서 방 · 워커 상태 · 전체 화면 |
| H9 | 업무를 **워크플로우(단계 + 승인 지점)** 로 보여주고 켜고/끄고/실행하게 하면, "무엇을 자동으로 하고 어디서 내가 확인하는지" 가 이해되는가 | 워크플로우 — 단계 파이프라인 · 지금 실행 · 승인 단계 |
| H7 | 일을 **부서(카테고리) 단위**로 묶으면 여러 에이전트의 일이 한눈에 정리되는가 | Task 카테고리 필터 · 작업 칩 |
| H8 | **마스터 1명 + 부서별 팀원 권한**이 직원과 함께 쓰는 사업장에 충분한가 | 설정 팀원 · 권한 → 이 사람으로 보기 |

## 3. 스코프 (In)

### 3.1 랜딩 페이지 (`/`)
- **섹션 1개.** 헤드라인 · 서브카피 · 봇 그래픽 · 작업 예시 카드 3장.
- CTA **'시작하기'** → 로그인 없이 `/app` 으로 이동.

### 3.2 서비스 페이지 (`/app`) — Arc 브라우저 레이아웃
- **창 전체 = 사업장 그라디언트**(고정 1종), 왼쪽 **투명 사이드바(LNB)**, 오른쪽 **둥근 흰 카드 1장**에 콘텐츠.
- 사이드바 구성 (위→아래)
  1. 뒤로/앞으로
  2. **커맨드 바 진입 필** (Arc 의 URL 바 자리) — `⌘K` 로도 열림
  3. **고정 타일 2×3** — 홈 · 사무실 · 메일(검토 필요 배지) · Task(사장님 할 일 배지) · 스케줄러 · 워크플로우(확인 필요 배지 합계).
     권한 없는 타일(메일=마스터만, 워크플로우=재무·소싱·마케팅 중 하나도 없을 때)은 숨긴다. 배지는 타일 오른쪽 위 모서리
  4. 사업장 이름
  5. **실시간 작업** — Arc 의 탭 목록 자리. 진행 중/대기/완료 작업, 현재 단계, 진행 바가 1.2초마다 갱신
  6. `+ 새 요청` (커맨드 바 열기)
  7. 하단 **보는 사람 칩 + ⚙️ 설정** — 호칭 · 말투 · 혼자 처리할 일/확인받을 일 토글 · 아침 브리핑 시간 · **팀원 · 권한**. 화면 안에서만 유지
- **커맨드 바** — 화면 중앙 오버레이. 자유 입력(=하루에게 요청) · 추천 프롬프트 · 메뉴 이동. ↑↓/Enter/Esc.

### 3.3 홈 (`/app`)
- **봇 그래픽(하루)** 이 손을 흔들며 맞이 + 시간대별 인사.
- **지난 접속 이후 보고** — 직전 접속 시각(localStorage, 첫 방문은 '어제 오후 6:12' 가정)과 함께
  처리 완료 / 확인 필요 / 인사이트 3종 카드.
- **하단 고정 입력부** — 추천 프롬프트 한 줄 + 입력창이 카드 하단에 고정되고, 위의 인사·보고·대화만 스크롤된다.
- **추천 프롬프트** 8개를 입력창과 같은 폭에 가로로 나열. 넘치는 쪽 끝은 그라데이션으로 사라지고,
  그 위에서 휠을 굴리면 좌우로 스크롤된다. 보내면 키워드 매칭된 더미 응답이 타이핑 인디케이터 후 표시.

### 3.4 실시간 작업 (`/app/live`)
- 진행 중 · 대기 · 오늘 완료 집계, 작업별 **단계 트래커**와 **최근 로그 4줄**.
- 사이드바 항목 클릭 시 해당 작업으로 스크롤·하이라이트(`#job-id`).

### 3.5 메일 연동 (`/app/mail`)
- 연결 계정 카드(Gmail · Naver 연결됨 / Outlook 미연결 → '연결하기' 누르면 연결된 것으로 표시).
- 필터: 전체 · 검토 필요 · 자동 처리됨. 메일마다 **AI 분류 라벨**과 **AI 처리 결과**.
- 펼치면 답장 초안 → **'승인 후 발송'** 시 처리됨으로 전환.

### 3.6 Task 목록 (`/app/tasks`)
- 할 일 · 진행 중 · 완료 그룹. 필터: 전체 · 사장님 할 일 · 하루가 맡은 일.
- 출처(메일/대화/스케줄러/리뷰) · 담당 · 긴급 · 마감 표시. 체크로 완료 토글.

### 3.7 자동화 스케줄러 (`/app/scheduler`)
- 6개 자동화(아침 브리핑, 메일 처리, 리뷰 답글, 주간 매출, 재고 발주, 인스타 예약 게시).
- 켜기/끄기 토글 · 주기 · 다음 실행 · 마지막 결과(실패 케이스 포함) · **'지금 실행'**(1.8초 후 성공 처리).
- **'+ 새 자동화'** — 이름 · 하는 일 · 주기(4개 중 선택)를 넣으면 목록 맨 위에 켜진 상태로 추가되고 잠깐 강조된다.
  실행 기록은 "아직 실행 기록 없음".

### 3.8 사무실 (`/app/office`) · 대시보드 (`/app/office/dashboard`)
- **사무실** — 크림 바닥 위 **아이소메트릭 선화** 장면(레퍼런스: 아이소메트릭 하드웨어 일러스트 스타일, 그림은 직접 그림).
  가운데 **하루 허브**(마스터), 허브와 점선 작업 경로로 이어진 **부서 에이전트 3명** — 상품 소싱 · 재무 · 마케팅.
  에이전트 = 부서 단위(작업 단위 아님). 예전 작업 단위 에이전트들은 역할 칩으로 남는다(예: 공장 탐색 · 가격 비교 · 중국어 통역).
  위에 진행 중 · 확인 필요 · 오늘 완료.
- **에이전트 상태** — 그 부서의 실시간 작업이 돌면 **일하는 중**(모니터 · 역할 타일 주황, 로봇 둥실, 허브에서 작업 큐브가 흘러감),
  없고 확인 필요가 있으면 **승인 대기**(주황 깃발), 아니면 평소 일 문장을 4초마다 바꾼다. 부서에 넘기지 않는 공용 일(메일 분류 · 브리핑)은
  **하루 직접** — 허브 라벨에 표시, 메일 답장 검토 건수 칩.
- **에이전트 카드** — 스테이션이나 라벨을 누르면 오른쪽 시트: 역할 칩 · 지금 하는 일(단계 · 진행률 · 이 작업 토큰) · 확인 필요(→ 처리할 화면) ·
  다음 차례 · **맡은 워크플로우 단계** · 평소 일 · 이번 달 완료 · 이번 달 토큰 · 워크플로우 열기.
- **권한** — 팀원으로 보면 권한 없는 스테이션은 회색 🔒. **⛶ 전체 화면** — 사무실 TV 상시 화면용.
- **📊 대시보드** 버튼 → 아래 대시보드. 대시보드에는 '← 사무실'. 예전 `/app/dashboard` 는 여기로 넘긴다.

**대시보드**
- **이번 달 돈 흐름**(재무 권한) — 매출 · 지출 · 순이익 · 마진율, 결제 예정(D-day), 월별 순이익 막대(엑셀을 올리면 7–9월 추가).
- **하루의 토큰 사용량** — 이번 달 사용 · 예상 비용(원) · 이번 접속 이후(실시간 작업 토큰이 1.2초마다 증가),
  월 예산 바(마스터만), 부서별 가로 막대, 많이 쓴 작업, 최근 14일 막대(마스터만).
  이미지 생성 SNS · 최저가 반복 탐색이 비싸다는 설명을 같이 둔다.

### 3.9 워크플로우 (`/app/workflows/:id` — 예전 `/app/finance` 는 재무 관리로 넘긴다)
- **상단 카드 3장** — 재무 관리 💰 · 상품 소싱 🏭 · SNS 자동화 📣. 켜짐/꺼짐 · 마지막 실행 · 확인 필요 배지. 권한 있는 것만 보인다.
- **관리** — 켜기/끄기 · **지금 실행**(단계가 0.8초마다 진행하다 **👤 승인 단계에서 멈춤** → '승인하고 계속') ·
  담당 부서 에이전트 · 트리거 · 이번 달 토큰 · 마지막 실행 결과. 접힘 영역에서 **실행 주기**와 **승인받을 단계**(단계 칩 켜고 끄기)를 바꾼다.
- **사용** — 워크플로우마다 아래 패널. 상태는 셸에 있어 탭을 옮겨도 유지된다(새로고침하면 초기화).

#### 3.9.1 재무 관리
- **엑셀 올리기** — 파일 선택/드래그 → 파일 읽기 · 시트 인식 · 항목 매핑 · 장부 반영 4단계 진행(실제 파싱 없음) →
  찾은 시트와 반영 위치 표. 이후 손익표 · 대시보드에 지난달이 채워진다.
- **월별 손익표** — 매출 · 상품 원가 · 물류·관세 · 광고비 · 인건비 · 창고 임대료 · 기타 · 지출 합계 · 순이익 · 마진율. 진행 중인 달 표시.
- **엑셀로 내보내기** — 손익표를 CSV(BOM, 엑셀에서 바로 열림)로 실제 다운로드.
- **자동 기록 규칙** 토글(입출금 문자 · 판매 채널 정산 메일 · 매일 밤 결산 시트 · 불분명 건 확인받기)과
  **최근 자동 기록** — 출처 칩, 확인 필요 건은 '매출로 기록 / 기타 수입' 으로 정리.

#### 3.9.2 상품 소싱
- **소싱 요청 카드** — 상품 · 수량 · 판매가 · 상태(공장 찾는 중 / 견적 도착 / 발주 완료).
- **견적 비교표** — 공장(1688 · 알리바바, 도시, 평점) · 단가(¥ → 원) · MOQ · 납기 · 개당 원가 · **예상 마진** · **국내 최저가 기준 마진** · 연락 상태.
  MOQ 를 맞추면서 마진이 가장 큰 공장에 '추천'. 서면 답이 없는 공장은 **☎ 전화 필요 · 긴급** → '통화 완료'.
- **공장 선택 → 👤 발주 승인** → "중국어 발주서 발송 · 선금 일정을 재무 관리에 추가" (더미).
- **+ 새 소싱 요청** — 상품 · 판매가 · 수량 → 공장 3곳에 문의 발송 상태 → 2.5초 뒤 견적 도착.
- 예상 마진 = 판매가 − 채널 수수료 11% − (공장 단가 × 환율 192 + 개당 해외 운송 · 관세 · 국내 택배). 광고비 제외.

#### 3.9.3 SNS 자동화
- 최근 게시물 도달 · 스토어 클릭 · 반응이 가장 좋은 게시물, 연결 채널(인스타그램 · 네이버 블로그 · 스레드).
- 상태 탭(승인 대기 · 예약됨 · 초안 · 게시됨 · 전체, 개수 포함). 승인 대기 → **승인하고 예약** / 다시 써줘, 초안 → 승인 대기로 올리기, 예약 → 예약 취소.
- **+ 새 게시물 만들기** — 상품 · 채널 → 1.5초 뒤 승인 대기 게시물 생성(더미 문구).

### 3.10 업무 카테고리 · 팀원 권한
- 부서 3곳 = 부서 에이전트: 재무 · 상품 소싱 · 마케팅 (고객 응대 · 물류 배송은 2026-10-28 제외). 부서에 넘기지 않는 공용 일은 **🤖 하루 직접**
  (마스터만 본다). Task · 실시간 작업 · 스케줄 · 토큰 사용량에 칩으로 붙는다.
  Task 는 카테고리 필터(개수 포함), 새 자동화는 '맡길 부서' 를 고른다.
- 팀원 3명: 사장님(마스터, 모든 부서) · 왕리(중국 소싱 담당 — 상품 소싱, 재무) · 김하늘(SNS 마케팅 담당 — 마케팅).
  마스터만 부서 칩을 켜고 끈다. **'이 사람으로 보기'** — 타일 · 실시간 작업 · Task · 스케줄 · 대시보드가 그 사람 권한으로 걸러지고,
  카드 상단 띠에서 사장님 화면으로 돌아간다. 권한 없는 주소로 들어오면 🔒 안내.

## 6. 데모 시나리오 (3분)

1. 랜딩 → **시작하기**
2. 하루가 인사하며 "어제 오후 6:12 이후" 보고 4건 — 실리콘 밀폐용기 재고 경고에 주목
3. 추천 칩 **'실리콘 밀폐용기 견적 비교 보여줘'** → 견적 4건 응답
4. 사이드바 실시간 작업이 움직이는 것 확인 → 클릭해 단계·로그 상세
5. 메일 → 검토 필요 3건 중 단체 주문 펼쳐 **승인 후 발송**
6. 스케줄러 → 실패한 '재고 발주 점검' **지금 실행**
7. `⌘K` → 자유 문장 입력 → 홈에서 응답 · 하단 ⚙️ 로 하루 말투 바꾸기
8. 워크플로우 › 재무 관리 → 결산 엑셀 끌어다 놓기 → 손익표에 7–9월 채워짐 · 확인 필요 입금 1건 '매출로 기록' · 엑셀로 내보내기
   › 상품 소싱 → 추천 공장 **선택** → **발주 승인** · **지금 실행** → 승인 단계에서 멈춤 → 승인하고 계속
   › SNS 자동화 → 승인 대기 게시물 **승인하고 예약** → 워크플로우 배지가 줄어드는 것 확인
9. 사무실 → 큐브가 흐르는 스테이션 · 깃발 든 스테이션 확인 → 눌러 에이전트 카드 → 워크플로우 열기 → **📊 대시보드** → 돈 흐름 · 토큰 사용량(이번 접속 이후 숫자가 오르는 것) 확인
10. 설정 → 팀원 · 권한 → 왕리 **이 사람으로 보기** → 메일 타일 사라짐 · 워크플로우는 재무 관리 · 상품 소싱만 · Task 는 재무 · 소싱만 → 띠에서 돌아가기

## 7. Open Questions

1. **보고의 단위** — "지난 접속 이후"가 맞나, "오늘/이번 주" 고정 창이 맞나? 며칠 만에 들어오면 보고가 길어진다.
2. **자동 발송 경계** — 어떤 일은 하루가 혼자 끝내고(메일 9건), 어떤 일은 승인을 받나(3건)? 사장님이 그 기준을 어디서 보고 바꾸나.
3. **표면** — 소상공인이 웹 앱을 열어볼까, 아니면 카카오톡 알림 + 승인 버튼이 주 표면이고 웹은 보조일까.
   (SoloSquad 결정 16 — 메신저 재도입 = v2.1.0 과 연결되는 질문)
4. **다점포** — 사업장이 여럿인 사장님에게는 사업장 전환이 필요한가, 통합 뷰가 먼저인가. (사업장 전환 UI 는 이번 범위에서 뺐다)
5. **권한의 깊이** — 부서 단위 보기/맡기기로 충분한가, 승인 권한(발주 승인은 사장님만)까지 나눠야 하나.
6. **토큰 표시 단위** — 사장님에게는 '토큰'보다 '원'이 맞나. 예산 초과 시 하루가 멈추나, 묻나.
7. **에이전트 인격** — 이름·그래픽을 가진 '직원' 메타포가 신뢰를 높이나, 과장된 기대를 만드나.
